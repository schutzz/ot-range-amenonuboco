マニフェストの作り方

このエディタは、OT/ICSサイバーレンジの構成を宣言するマニフェスト（YAML）を書くための道具です。 環境そのものは、書き出したYAMLを手元で docker compose に通して立ち上げます。

まず試す

右上のプルダウンから 電力・上下水道・重要製造業 のいずれかを選ぶと、実際に動作確認済みの構成が読み込まれます。 まずはこれを触って、編集が図とYAMLにどう反映されるかを見るのが早道です。ゼロから作る場合は「新規（空から作る）」を選びます。

作る順序

後の項目が前の項目に依存するため、この順序で進めてください。 依存先が無いと選択肢が出ません（例：l3-router の資産を作る前は、ゲートウェイのプルダウンが空です）。

  1. セグメントを作る — ネットワークの区画です。名前・CIDR・種別（OT LAN／WAN境界／観測用など）を決めます。 観測（ミラーリング）を使うなら、観測用のセグメントを1つ用意しておきます。
  2. 資産を足す — コンテナ1つが資産1つです。ロールを選ぶと、必要な権限（cap_add 等）が自動で決まります。 ゲートウェイ役には l3-router ロールを選び、すべてのセグメントに接続させます。
  3. ルーティングでゲートウェイを選ぶ — セグメント間の経路が自動生成されます。
  4. 計装層を有効にし、ミラー集約先セグメントを選ぶ — 残りのセグメントが自動的に観測対象になります（除外したいものだけチェック）。 ゲートウェイがミラーリングの実行主体になるため、ゲートウェイは観測対象と集約先の全セグメントに静的IPが必要です（不足すると警告が出ます）。
  5. 構造化層を有効にし、プロトコルと出力先indexを登録する — tsharkが該当プロトコルを解析し、Elasticsearchへ投入する配線が生成されます。

画面の見方

  • 中央の図 — 編集するたびに描き直されます。セグメントの枠色と下端バッジが「観測対象／ミラー集約先／観測外（死角）」を示します。破線の矢印がミラーされるトラフィックの流れです。
  • 図の下の帯 — 検証結果です。✕ はYAMLとして出す前に直すべきもの、! は宣言としては妥当だが実際に環境を立ち上げた時に問題になるものです。
  • 右のYAML — 常に最新の状態が出ています。手書きする場合の書き方の参考にもなります。

書き出したあと

「YAMLをダウンロード」で保存し、リポジトリを手元に用意したうえで実行します。

python platform/cli.py provision <保存したファイル>.yaml
docker compose -f <保存したファイル>.docker-compose.yml up -d

ネットワーク図（自己完結HTML）も生成できます。記事や資料に載せる図はこちらを使ってください。

python platform/cli.py diagram <保存したファイル>.yaml

つまずきやすいところ

  • 起動コマンドに二重引用符を使わない — 生成されるコマンドは最終的に sh -c "..." で包まれるため、中の二重引用符が包みを破ります。単一引用符を使ってください（警告が出ます）。
  • コメントは保持されません — 書き出しは常に新しいファイル（<name>.generated.yaml）です。手書きのマニフェストを読み込んで書き戻すと、そこに書かれていた説明は失われます。
  • 検知ロジック・攻撃・ダッシュボードはここでは作れません — それらはマニフェスト外のスクリプトとして書く領域です。エディタが扱うのは環境の「器」の部分（構成・観測・構造化）までです。

詳しい解説は エディタの使い方、 記法の全リファレンスは マニフェスト記法ガイド にあります。
